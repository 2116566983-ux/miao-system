# 云端部署指南 · 用一条链接给全班上课

本文说明如何把系统发布到 **Streamlit Community Cloud**（官方免费托管），
最后得到一个公网链接，老师和学生**用浏览器直接打开就能上课**。

> 如果你有一台带 GPU 的服务器、想要完整的 AI 生成能力，
> 请看 [deploy-guide.md](deploy-guide.md) 的形态 B。两份文档是两条不同的路：
>
> | | 本文（云端托管） | deploy-guide 形态 B（自建服务器） |
> |---|---|---|
> | 学生要装东西吗 | 不要 | 不要 |
> | AI 生成 | ❌ 不可用（云端没 GPU） | ✅ 可用 |
> | 图数据库查询 | ⚠️ 降级为 CSV 内存图 | ✅ 连真实 Neo4j |
> | 费用 | 免费 | 要一台服务器 |
> | 维护成本 | 几乎为零 | 要管进程、端口、证书 |

## 一、先接受两个降级，再决定要不要走这条路

云端托管是**共享资源**，拿不到本地环境和 GPU。所以有两处必然降级：

| 环节 | 云端表现 | 影响 |
|---|---|---|
| **⑥ 知识图谱** | 连不上你本机的 Neo4j → 自动降级为**读 CSV 在内存里建图** | **教学不受影响**。Cypher 查询的结构、语法、结果都一样，只是数据来自 CSV 而不是数据库服务。学生练的是"怎么写查询"，不是"怎么装数据库" |
| **② AI 重组生成** | 云端没有 GPU，ComfyUI 与本地模型都不可用 | 生成功能会显示降级提示。其他 7 个页面全部正常 |

**⑥ 的降级已实测验证**（在无 Neo4j 的环境下跑全部 6 个预设查询）：

| 预设查询 | CSV 内存图结果 |
|---|---|
| ① 一朵纹样的全部变体 | ✅ 3 行 |
| ② 两跳：变体的变体 | ✅ 3 行 |
| ③ 一张图的全部邻居 | ✅ 6 行 |
| ④ 共色的图片 | ✅ 1 行 |
| ⑤ 按地域统计纹样分布 | ✅ 1 行（`地域=未标注，图片数=1000`，计数正确） |
| ⑥ 跨维度：技法 × 地域 | ✅ 0 行（**预期内**，这两个字段还没标注） |

关系数量的差异也查清了，**不影响教学**：

| | 节点 | 关系 |
|---|---|---|
| CSV 内存图 | 1279 | 3739 |
| 真实 Neo4j | 1279 | 4739 |

差的 1000 条是 `BELONGS_TO`（图 → 所属组）。真实库里同时存在
`HAS_VARIANT`（组 → 图）和 `BELONGS_TO`（图 → 组）两条**方向相反、
表达同一事实**的关系（导入脚本里就是这么建的，为了让两处既有代码都能用）；
CSV 内存图只建了 `HAS_VARIANT` 那一侧。
⑥ 页的 6 个查询用的都是 `HAS_VARIANT` / `DERIVED_FROM` 等，所以结果一致。

**结论**：如果这门课的重点是
「数据整理 → 图数据库 → 检索 → 提取 → 标注 → 互评」这条主线，
云端部署完全够用，第一节课就能上。

如果要现场演示 AI 生成，那必须用自建服务器（deploy-guide 形态 B），
或者在本地机器投屏演示、其余时间用云端链接。

## 二、图片是怎么解决的（重要）

课堂要用的 1000 张原图有 **155MB**，放不进 GitHub 仓库
（单文件有 100MB 硬上限，仓库也不建议超过 1GB）。

但课上没图，检索页、标注页、提取页就都用不了。所以：

```
原图 155MB  →  tools/build_thumbs.py  →  缩略图 51MB  →  随仓库发布
```

缩略图已经生成好放在 `data/images/`，**已经随仓库提交**，
你不需要再做这一步。它们的规格是：

- 长边 ≤ 560px，JPEG 质量 78
- 屏幕上看着够清楚（花瓣形状、针脚走向都能辨）
- **不适合**下载去做印刷级设计 —— 要高清用原图

`app/paths.py` 的查找顺序保证云端会读到这批图：

```
1. 环境变量 MIAO_IMAGE_ROOT     ← 本地开发想用高清原图就设这个
2. 项目内 data/images/          ← 云端走这条（缩略图）
3. 项目内 images/
4. 常见外部位置（兜底）
```

所以**本地和云端看到的是同一批图**，不会出现"我这能看、你那不能看"。

### 有一张图会因缩放而"不可标注"（已知且可接受）

`build_metadata.py` 的判据是「短边 < 100px 则不适合做区域标注」。
`basic_828.jpg` 原图是 **2409×362** 的极端宽幅图，长边缩到 560 后变成
**560×84**，短边掉到 100px 以下 —— 于是它从"可标注"变成"不可标注"。

- 影响范围：1000 张里就这 1 张
- 为什么会这样：极端宽高比的图，缩长边必然压短边，两者不可兼得
- 为什么不单独处理它：把长边放宽到能保住短边 100px，这张要保留 1500px+ 的
  长边，会白白多占几 MB 仓库体积，为 1 张图不划算
- 系统行为：它仍会出现在检索页（只是标注页会提示"不宜标注"），
  学生看到的图不会少

`tests/test_core.py` 已把这一点固化成断言：
如果量的是 `data/images/`，可标注数按 **730** 校验（原图目录按 731）。
这样"漂移"变成了一条**写在测试里的已知事实**，而不是哪天突然失败让人困惑。

> 换一批数据时重新生成：
> ```bash
> python tools/build_thumbs.py --src <原图目录>
> ```
> 想调清晰度：`--max-edge 800 --quality 85`（体积会变大，注意仓库上限）。

## 三、部署步骤

### 步骤 1：把代码推到 GitHub

仓库需要是**公开**的（Streamlit 免费版只能连公开仓库）。

如果你还没建仓库，先建一个**空的**公开仓库（不要勾 README /
.gitignore / license，否则第一次 push 会被拒）：

```bash
cd miao-system
git remote add origin https://github.com/<你的用户名>/miao-system.git
git branch -M main
git push -u origin main
```

> 推送前请确认仓库里没有凭据。本项目已经把
> `start.local.bat`（存真实密码的文件）放进 `.gitignore`，
> 仓库里只有不含真实值的 `start.local.bat.example`。
> 自查一下：
> ```bash
> git grep -i "MiaoEmbroi\|password\s*=" -- ':!*.example' | head
> ```
> 没有输出就说明干净。

### 步骤 2：在 Streamlit Cloud 建应用

1. 打开 <https://share.streamlit.io/>，用 **GitHub 账号登录**
2. 点 **Create app** → 选 **Deploy a public app from GitHub**
3. 填三项：

   | 字段 | 填什么 |
   |---|---|
   | Repository | `<你的用户名>/miao-system` |
   | Branch | `main` |
   | **Main file path** | **`app/streamlit_app.py`** |

   > ⚠️ Main file path 一定要写全 `app/streamlit_app.py`。
   > 只写 `streamlit_app.py` 会找不到文件 —— 因为入口在 `app/` 子目录里。

4. 点 **Deploy**，等 2–5 分钟首次构建

构建完成后会得到一个链接，形如：

```
https://<你的应用名>.streamlit.app
```

**这个链接就是给学生和老师的。**

### 步骤 3：验证

打开链接，逐项确认：

- [ ] 首屏是 **⓪ 课程导航**，能看到"32 课时 / 4 个教学单元"
- [ ] 填学号、选层次，进度行显示 `0 / 4 单元已完成`
- [ ] **① 检索纹样**页能出图（这是图片有没有生效的关键）
- [ ] **⑥ 知识图谱**页顶部显示的是"CSV 内存图"而不是"已连接 Neo4j"（预期内）
- [ ] **② AI 重组创作**页显示降级提示（预期内）
- [ ] **⑤ 标注纹样**能填表提交

## 四、常见问题

### Q：链接打开是白屏，或者要等很久？

免费实例在**没人访问一段时间后会休眠**，第一个人打开要等
20–60 秒唤醒。这是免费版的机制，不是坏了。
**建议上课前 5 分钟自己先点开一次**，把实例唤醒。

### Q：检索页没有图？

说明 `data/images/` 没推上去。检查：

```bash
git ls-files data/images | wc -l     # 应该是 1000
```

如果是 0，说明被 `.gitignore` 挡住了 —— 本项目已确认不会，
但如果你改过 `.gitignore` 就要复查 `data/images` 那一节。
补推：

```bash
git add -f data/images
git commit -m "chore: 补推课堂缩略图"
git push
```

推完在 Streamlit Cloud 点 **Reboot app**。

### Q：学生提交的标注会保存吗？

**会，但不持久。** Streamlit Cloud 的容器是**临时的**——
重新部署、休眠重启都可能让写入的文件丢失。

所以云端形态的定位是「**上课演练**」：
学生熟悉流程、理解每个字段的含义。
**正式的标注数据请在本地或自建服务器上做**（见 deploy-guide 形态 B），
或者课后把 `annotation/` 目录导出备份。

> 这一点必须提前跟学生说清楚，否则会有人认真标了两小时然后数据没了。

### Q：能不能连上我这台电脑的 Neo4j？

不能。云端在公网，你的 Neo4j 在本地且没有公网地址。
即使做了内网穿透，把数据库暴露到公网也是**很危险**的做法，不要做。

用 ⑥ 页的 CSV 内存图教学即可 —— 查询语法、结果结构完全一致。

### Q：想改成自己的休眠策略 / 加密码？

免费版都没有。要这些能力就得自建服务器（deploy-guide 形态 B）。

## 五、一句话总结

> **代码推 GitHub → Streamlit Cloud 选 `app/streamlit_app.py` → 拿到链接 → 发给学生。**
>
> 图片已随仓库发布（51MB 缩略图），无需额外操作。
> ⑥ 降级为 CSV 内存图（教学等价），② 生成不可用（云端无 GPU）。
> 标注数据不持久，正式数据请在本地做。
