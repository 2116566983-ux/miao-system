# 苗绣纹样创作系统

《数据采集与清洗》课程 · 苗绣纹样数字化教学模块 —— 完整闭环原型。

**链路**：检索纹样 → 选择元素 → AI 辅助重组 → 作品归档

面向**公选课学生**：打开网页即可用，全部按钮操作，不需要编写任何代码。

---

## 一、快速开始

### 1. 安装依赖

```bash
pip install streamlit pandas pillow neo4j requests
```

### 2. 启动系统

在项目根目录 `miao-system/` 下执行：

```bash
streamlit run app/streamlit_app.py
```

浏览器会自动打开 `http://localhost:8501`。若未自动打开，手动访问该地址即可。

### 3. 关闭系统

在终端按 `Ctrl + C`。

### 4. 运行状态（自动检测）

系统启动时会自动探测环境，无需配置：

| 状态 | 检索 | 生成 | 归档 | 说明 |
|---|---|---|---|---|
| 图数据库 + ComfyUI（本地或远端） | ✅ | ✅ | ✅ | 完整闭环 |
| 仅图数据库 / 仅 CSV | ✅ | ❌ | ✅ | 可检索、可看作品 |
| 什么都没有 | ✅ | ❌ | ✅ | CSV 降级模式，检索照常 |

界面右上角两个徽标会显示当前状态。**不装任何东西也能用检索功能。**

### 5. 用别的机器上的 ComfyUI

如果实验室/学校有带 GPU 的服务器并且已经跑着 ComfyUI，
**不用在本地装显卡或模型**，设四个环境变量即可（系统自动建 SSH 隧道）：

```bat
set COMFYUI_SSH_HOST=你的服务器地址
set COMFYUI_SSH_PORT=22
set COMFYUI_SSH_USER=你的用户名
set COMFYUI_SSH_KEY=C:\path\to\id_rsa    rem 或用 COMFYUI_SSH_PASSWORD
```

详见 **`docs/remote-comfyui.md`**。

> ⚠️ **有个前提容易踩坑**：ComfyUI 能连上 ≠ 能出图。
> 服务器上必须有生成模型。系统会连上后自动盘点模型并挑选匹配的工作流模板，
> 缺模型时会明确告诉你还缺什么。

## 二、学生怎么用

界面分**八个标签页**。学生**只需要浏览器** —— 不用装软件、不用写代码。
第一页是课程导航，按上面写的顺序走完，就是这门课的全部任务。

> **关于编号**：标签页上的圈码表示**教学顺序**（① 最先学，⑥ 最后学），
> 而页面**排列顺序**略有不同 —— ⑦ 作品展示墙排在 ③ 我的作品旁边，
> 因为「看自己的作品」和「看全班作品并互评」是同一件事的两面，
> 放一起才好对照。编号与位置不一致是有意为之，不是排错了。
> 各单元用到哪几个页面，在 ⓪ 课程导航里逐个单元列了出来。

### ⓪ 课程导航

**这一页回答「这门课一共要做什么、我现在做到哪了」。**

- 填**学号 / 姓名**（进度与作品都记在这个身份下）
- 选**学习层次**：
  - **基础层**（全体学生）—— 全程网页操作，不需要装软件
  - **拓展层**（计算机 / 数据专业）—— 在此之上额外学 Cypher 与 Python 调用
- 看**总进度**：`已完成 N / 4 单元 ｜ 已标注 X 组 ｜ 作品 Y 件`
- 下面按顺序列出**四个教学单元**，每个单元给出：
  课时（理论 / 实践）、主题、要做的事（基础层）、本单元产出、
  用到哪几个页面、配套实验指导书文件名
  - 选「拓展层」时，每个单元会多出一个折叠块，写本单元的额外技术要求

全课 **32 课时 = 理论 16 + 实践 16**，四个单元正好把八个页面串成一条线。

### ① 检索纹样

1. 在**左侧栏**筛选：纹样类型（原始图 / 纹理变体 / 色彩变体 / 拼贴合成图）、
   画面方向、是否只显示可标注的
2. **纹样属性**一栏可按题材、地域、技法、主色调筛选
   —— 这四项依赖 ④ 标注页的数据，未标注时为不可选状态
3. 浏览大图网格，点击「**加入我的选择**」收集素材
4. 用「上一页 / 下一页」翻页

### ② AI 重组创作

1. 确认已选素材（1–2 张）
2. 选择创作模式：
   - **单图重组** —— 把一张纹样重新演绎
   - **多纹样组合** —— 把两张纹样合成新作品（需 ≥2 张素材）
3. 填**学号 / 姓名**（作品必须记录作者）
4. 调**创作强度**：轻微调整 / 中等重组 / 大幅创作
5. 改**创作描述**，或保留默认的苗绣风格提示词
6. 点「开始生成」
7. 点「查询进度 / 取回结果」查看进度

> **注意**：ComfyUI 生成是**异步**的，提交后需要点按钮查询进度，
> 不会自动刷新。队列中有人排队时会显示"运行 N 个 / 等待 M 个"。

### ③ 我的作品

这里是**个人工作台**，不只是作品列表：

- 默认只看**自己的作品**（按学号筛选，可改为查看全部）
- 每件作品都记录了**原始素材、提示词、随机种子、生成时间**，
  可作为课程过程性材料
- **写设计说明** —— 每件作品都要写一段：用了哪些纹样元素、
  为什么这样组合、想表达什么。这是第三单元的核心产出
- 有一项「**只看还没写设计说明的**」筛选，方便检查自己漏了哪件
- 能看到**别人给你的互评**（优点 + 建议）
- 能看到**教师审核结果**（通过 / 需修改 / 待审核，带颜色区分）
- 可导出 `works.csv`

### ⑦ 作品展示墙

**全班作品放在一起看** —— 这是第四单元「互评」的场所。

- 三列网格，每件作品显示**缩略图、作者、设计说明、收到几条互评**
- 筛选：按创作方式（单图重组 / 多纹样组合）、只看**我还没评过的**
- 排序：**最新在前** / **互评最多**
- 点开每件作品可看详情，并**当场写互评**：
  - **先说优点**（必填）
  - **再给一条具体建议**（必填）
- **不能评自己的作品**（系统会拦下）

> 互评的关系是「多对一」—— 一件作品可以被很多人评，
> 一个人也能评很多件。所以它单独存一张表（`works_peer_review.csv`），
> 不写在作品行里。写进作品行的话，第二个人评完就把第一个人覆盖了。
> 同一个人重复评同一件作品会**更新为最新一条**，不会留下两条互相矛盾的记录。

### ④ 提取纹样

**这一步回答一个容易被忽略的问题：我们采的到底是什么数据？**

数据集里的图是**绣品实物的照片** —— 一块靛蓝土布上绣着彩色花枝，
边上还常有黑色填充条。但课程要研究的「纹样」是一个**符号 / 特征**，
它应该可提取、可比较、可复用，而不是「一张附着在布料上的照片」。

打开界面 → **④ 提取纹样**：

1. 左侧从图库里选一张绣品照片（或上传自己的照片）
2. 点「开始提取纹样」
3. 程序自动完成三件事：
   - **去黑边** —— 裁掉照片四周的纯黑填充条
   - **估底布** —— 从图像外圈统计出布的颜色（布总是铺到边上的）
   - **分离绣线** —— 用「局部粗糙度 + Otsu 阈值 + 颜色约束」把绣线从布上分出来
4. 右侧四种查看方式（**默认为 3D 立体展示**）：

| 视图 | 看什么 | 教学含义 |
|---|---|---|
| ④ 3D 立体展示（可转动） | 真实三角网格 + 浮雕厚度，可拖动旋转 | 纹样是**实物**，有起伏、有厚度，不是一张平面图 |
| ② 透明纹样（棋盘底） | 提取结果本身 | 纹样已是**独立符号**，不再依附布料 |
| ③ 四方连续 | 镜像拼贴成图案 | 符号一旦提取，就能**无限复用**（布料/壁纸/UI 底纹） |
| ① 原图对照 | 原照片 + 纹样在画面中的位置 | 看清「多少像素是底布背景，多少才是信息」 |

3D 视图下方有三个调节项：**网格精细度**（分辨率）、**网格密度**（三角面数）、
**浮雕厚度**。鼠标拖动可任意角度旋转，滚轮缩放。
地面带刻度格，用来给纹样一个尺度参照。

**为什么用棋盘底看提取结果**：不少纹样的花瓣本身就是**白线**，
放在白色页面上会和背景糊成一片，看起来像「花瓣被挖空了」。
棋盘格深浅交替，能立刻区分「真的是透明孔洞」和「白色的绣线」。

> 提取是**纯本地计算**（只用 numpy + PIL），不联网、不占用服务器 GPU。
> 提取出的透明 PNG 存放在 `data/motifs/`，可下载用于后续设计。

### ⑤ 标注纹样

- 系统自动逐个显示纹样，**看图点选**补充题材、地域、技法、主色调等属性
- 一组只需标一次，**4 个变体自动继承**
- 顶部有进度条，可看到自己的标注量和全班的完成度
- 机器参考值会显示在旁边（明确标注为「仅供参考」），帮助判断
- 前 4 项（题材/地域/技法/主色调）是必填；看不出就选「未确定」，**不要猜**

> 这些属性程序推断不出来，只能靠人。但补上之后，① 检索页就能按这些维度筛选了。
> 教师可在页面底部「教师操作用」里一键合并到检索数据。

> 学生无需接触任何技术字段。文件名、像素尺寸、质量状态等信息默认隐藏。

### ⑥ 知识图谱

**这一页讲的是「数据怎么组织」，而不是「数据怎么存」。**

三个板块：

1. **图数据库的三个基本概念** —— 节点 / 关系 / 属性。
   每个概念都配一句苗绣场景的解释：一张图是节点，
   「这张图派生自那张图」是关系，`宽/高/方向` 是属性。
   下面直接列出本项目的实际图模型（10 类节点、11 类关系）和当前真实数量。

2. **同一份数据，两种存法** —— 用一张对照表讲清「表格」和「图」的差别，
   并把 **Cypher 和 SQL 并排**放在一起。核心区别：
   图里的关系是**一等公民**，表里的关系只是**藏在列里的外键**。

3. **动手查询** —— 6 个预设查询，点一下就用**真实数据**跑给你看：

| # | 问题 | 考察的图能力 |
|---|---|---|
| ① | 一朵纹样的全部变体 | 一跳关系 |
| ② | 变体的变体（两跳） | `*1..2` 变长路径 |
| ③ | 一张图的全部邻居 | 无向遍历 |
| ④ | 共色的图片 | 共享邻居（反向推荐） |
| ⑤ | 按地域统计纹样分布 | 聚合 |
| ⑥ | 技法 × 地域 | 跨维度 |

其中 **② 最有说服力**：SQL 里要写死 JOIN 层数，
图上用 `*1..2` 一句话就能问「两跳之内所有变体」。

> **⑤⑥ 现在返回 0 行，这是正常的** —— 地域、技法字段还没标注。
> 页面会明确提示：**「数据不完整本身就是《数据采集与清洗》要处理的问题」**，
> 并引导你去 ⑤ 标注纹样 补上，回来这里立刻就有数据。

> 页面右上角显示当前数据源：**「已连接真实图数据库（Neo4j）」**
> 或「本地数据（CSV）」。两者查询结果结构完全一致，
> 所以就算没装 Neo4j，这一页照样能上课。

## 三、教师怎么用

### 更换图片目录

左侧栏展开「**高级设置（教师用）**」：

- **图片所在文件夹** —— 填写图片实际存放路径
- **显示技术信息** —— 勾选后在缩略图下方显示文件名、尺寸、质量状态

### 作品审核

左侧栏「**教师审核**」：

1. 从下拉框选择作品
2. 选审核结果（通过 / 需修改 / 待审核）
3. 填写评语
4. 点「保存审核」—— 若已连接图数据库，会同步写入

### 更新元数据

图片有增删后，重新生成清单：

```bash
python build_metadata.py --src "图片目录路径" --out metadata/images.csv
python build_graph_csv.py --src metadata/images.csv --out graph/csv
```

重启应用即可生效。

## 五、提取纹样（把纹样从照片里分离出来）

**这一步回答一个容易被忽略的问题：我们采的到底是什么数据？**

数据集里的图是**绣品实物的照片** —— 一块靛蓝土布上绣着彩色花枝，
边上还常有黑色填充条。但课程要研究的「纹样」是一个**符号 / 特征**，
它应该可提取、可比较、可复用，而不是「一张附着在布料上的照片」。

### 在网页里提取（④ 提取纹样）

1. 左侧从图库里选一张绣品照片（或上传自己的照片）
2. 点「开始提取纹样」
3. 程序自动完成三件事：

| 步骤 | 做什么 | 为什么 |
|---|---|---|
| 去黑边 | 裁掉照片四周的纯黑填充条 | 黑边既不是底布也不是纹样 |
| 估底布 | 从图像外圈统计布的颜色 | 布总是铺到边上的 |
| 分离绣线 | 局部粗糙度 + Otsu 阈值 + 颜色约束 | 绣线有起伏纹理，底布平滑 |

4. 右侧四种查看方式：

| 视图 | 看什么 | 教学含义 |
|---|---|---|
| **④ 3D 立体展示（可转动）** | 有厚度的三维实体网格 | 刺绣是**实物**，有体积、有起伏——纹样是「物」不是「图」 |
| ② 透明纹样（棋盘底） | 提取结果本身 | 纹样已是**独立符号**，不再依附布料 |
| ③ 四方连续 | 镜像拼贴成图案 | 符号一旦提取，就能**无限复用**（布料/壁纸/UI 底纹） |
| ① 原图对照 | 原照片 + 纹样在画面中的位置 | 看清「多少像素是底布背景，多少才是信息」 |

**3D 立体展示台**（默认视图）——拖动旋转、滚轮缩放、右键平移：

- 纹样被还原成一块**有厚度的实体**（正面 + 背面 + 侧面），
  贴着纹样原本的颜色，放进一个有台面、有光照的三维场景里。
- 可调三个参数：**网格精细度 / 网格密度 / 浮雕厚度**。
- 高度由**三层**叠加，各管各的尺度：底形（这块布多厚）、
  **纹路（花朵/叶脉/回纹凸起——这层是主体）**、肌理（丝线细起伏）。
  其中纹路层用的是「到**底布色**的颜色距离」——苗绣底布是整块靛蓝，
  绣花是彩色丝线，两者颜色差很大，所以这个距离天然就是一张绣花掩膜，
  和肉眼看到的图案一致。
- 不做「距边缘的距离」主导：那是"整块布被剪成的形状"，
  出来是一块鼓起的馒头；真实绣片是**平的布 + 微微凸起的线迹**。

**为什么用棋盘底看提取结果**：不少纹样的花瓣本身就是**白线**，
放在白色页面上会和背景糊成一片，看起来像「花瓣被挖空了」。
棋盘格深浅交替，能立刻区分「真的是透明孔洞」和「白色的绣线」。

**参数**：「保留最大连通块数」控制保留几块纹样。纹样常由多块
（花瓣、花心、边饰）组成，一般 4–8 合适；「显示全部连通块」用于调试
——判断是「纹样被切碎了」还是「底布没去干净」。

> 提取是**纯本地计算**（只用 numpy + PIL），不联网、不占用服务器 GPU。
> 提取出的透明 PNG 存放在 `data/motifs/`，可下载用于后续设计。
> 只有 3D 视图需要 plotly（可选），不装则降级为静态灰度高度图。
> 开发期可用 `python tools/render_mesh_preview.py <图片名>` 把网格
> 离线渲染成 PNG，用来快速检查立体效果。

### 效果（实测）

| 样本 | 底布 | 纹样占比 | 结果 |
|---|---|---|---|
| basic_0 | 靛蓝 | 49% | ✓ |
| basic_8 | 墨绿 | 67% | ✓ |
| basic_996 | 近黑 | 65% | ✓（此前算法完全失效） |

运行 `python app/motif_extract.py` 可对数据集做自检。

## 六、标注纹样（解锁检索筛选的关键）

系统里地域、技法、色彩这些筛选维度**目前全部为空**，因为它们无法由程序推断。

### 为什么是 245 组而不是 1000 张

数据集是 **250 张原图 × 4 种变体**，4 个变体是同一张苗绣的不同版本。
所以标注**标在分组上，4 个变体自动共享** —— 人工只需标 245 次，不是 1000 次。

### 推荐方式：在网页里标注（⑤ 标注纹样）

打开界面 → **⑤ 标注纹样** 标签页：

3. 点「**保存并看下一组**」，自动跳到下一个未标注的
4. 顶部进度条实时显示完成度

不需要编辑任何 CSV 文件，也不需要跑命令行。

**教师**：标完后在页面底部「教师操作用」里点「合并到检索数据」，
① 检索页的地域、技法筛选立刻生效。也可以导出标注表发给助教。

### 备用方式：命令行填表（批量/离线）

如果习惯用 Excel 批量处理：

```bash

python build_annotation_sheet.py build

# 2. 用 Excel 打开 annotation/annotation_sheet.csv 填写
```

> 网页方式的数据存在 `annotation/annotations.csv`（结构与标注表不同，
> 含标注人和时间戳，便于多人协作统计）。两种方式不冲突，网页方式是主推荐路径。

详细字段定义、取值参考、分工建议见 **`annotation/标注操作指南.md`**。

### 已验证的机制

- 标注 1 组 → 提交 → 落盘，4 个变体自动继承 ✅
- 标注表 → `images.csv` → `nodes_groups.csv` 全链路贯通 ✅
- 标注后按地域筛选能正确筛出该组全部 4 个变体 ✅

### 关于机器参考值的重要说明

标注表里 `【参考】` 开头的 8 列是机器统计的，**不要直接采信主色**。

实测原因：这批图多为实物拍摄，**普遍带黑色边框或暗背景**，
机器统计出的首位色常常是背景色而非纹样主色。例如一张桃红花卉刺绣，
机器会报"黑色"。

**建议用法**：把 `【参考】机器统计配色线索` 当作"这张图里有哪些颜色"的提示，
主色最终由人眼判断后填入 `【待填】主色调`。
对称、明度、疏密三项参考值相对可靠，但对称度因拍摄角度影响也有偏差。

## 九、接入 Neo4j（已实现并在本地实测通过）

系统支持**双数据源**：连得上数据库走图查询，连不上自动降级读 CSV，界面功能不变。

> **当前状态**：本地 Neo4j 社区版 5.26 已跑通，数据已导入
> （**1279 节点 / 4739 关系**），检索页与 ⑥ 知识图谱页均以真实 Cypher 执行。
> 部署细节与踩坑记录见 `docs/技术文档.md` §6.5。

### 方式 A：独立版 Neo4j（本项目实测路径，推荐）

**第 1 步：装 Java 17**

Neo4j 5.x 需要 Java 17。推荐 [Eclipse Temurin](https://adoptium.net/)。
装好后 `java -version` 应显示 17.x。

**第 2 步：下载 Neo4j 社区版**

从官网 https://neo4j.com/deployment-center/ 下载 Community Server 的 ZIP，
解压到任意目录（本项目用的路径：`C:\Users\21165\miao-neo4j\neo4j-community-5.26.0`）。

> 若官网下载被拒（返回 `403 configured to block access from your country`），
> 换国内镜像获取 ZIP 即可，包内容一致。

**第 3 步：调内存（跑在笔记本上必做）**

编辑 `conf/neo4j.conf`，加上：

```
server.memory.heap.initial_size=1g
server.memory.heap.max_size=1g
server.memory.pagecache.size=512m
```

**第 4 步：设初始密码（必须在首次启动数据库之前）**

```bash
cd <Neo4j 解压目录>
export NEO4J_HOME="$(pwd)"

java -cp "lib/*" org.neo4j.cli.AdminTool dbms set-initial-password 你的密码
```

**第 5 步：启动**

**推荐直接双击项目里的 `tools/start_neo4j.bat`**（Windows，已配好路径与密码）。
Linux / macOS 用下面的等价命令：

```bash
java -cp "lib/*;conf" \
  -Dserver.directories.neo4j_home="$NEO4J_HOME" \
  org.neo4j.server.CommunityEntryPoint \
  --home-dir "$NEO4J_HOME" --config-dir "$NEO4J_HOME/conf"
```

启动后访问 http://localhost:7474 可看到 Neo4j Browser。关掉窗口即停止数据库。

> **为什么不直接用官方的 `bin\neo4j.bat`？**
> 它在本机会报一个被吞掉的乱码错误（`WriteErrorException`）——
> 因为它是转调 `.ps1`，PowerShell 层把真实报错埋了。
> 上面这条直接调 Java 入口的命令，报错是完整可见的。
>
> 另外 `AdminTool server console` 也走不通（会抛
> `not an enhanced execution context`），必须用 `CommunityEntryPoint`。

**第 6 步：导入数据**

```bash
# Windows
set NEO4J_PASSWORD=你的密码
python tools\import_to_neo4j.py

# Git Bash / Linux / macOS
export NEO4J_PASSWORD="你的密码"
python tools/import_to_neo4j.py
```

加 `--wipe` 会先清空再导入（默认不清空）。
全部使用 `MERGE`，**可重复执行不产生重复数据**。

### 方式 B：Neo4j Desktop / 已有实例

把 `graph/csv/` 下三个 CSV 复制到 Neo4j 的 import 目录，
然后依次执行：

```bash
cypher-shell -u neo4j -p 你的密码 -f graph/schema.cypher
cypher-shell -u neo4j -p 你的密码 -f graph/import.cypher
```

### 连接界面

设置环境变量后启动：

```bash
# Windows (Git Bash)
export NEO4J_URI="bolt://localhost:7687"
export NEO4J_USER="neo4j"
export NEO4J_PASSWORD="你的密码"

streamlit run app/streamlit_app.py
```

Windows 用户也可直接改 `start.bat` 里的 `NEO4J_PASSWORD` 再双击。

连接成功时界面右上角显示「**图数据库**」徽标；未连接显示「本地数据」。
侧边栏「高级设置」中会说明未连接的具体原因。

### 两种模式的区别

| | CSV 模式 | 图数据库模式 |
|---|---|---|
| 分组去重 | 内存中完成 | Cypher 查询天然去重 |
| 变体派生链 | 不可用 | 可追溯完整链路 |
| 标注进度看板 | 不可用 | 教师端可用 |
| ⑥ 知识图谱页 | 内存图（等价实现） | **真实 Cypher 执行** |
| 数据更新 | 重跑脚本 | 重跑导入即可 |

> **说明**：即使不装 Neo4j，界面也能完整使用（含 ⑥ 知识图谱页）。
> 图数据库的价值在于标注数据回填后，地域、技法、色彩等维度可以通过
> 变长路径查询展开，这是 CSV 模式无法替代的。

## 十、图模型要点

完整说明见 `graph/model.md`。核心决策：

**为什么同时用 `MotifGroup` 节点和 `DERIVED_FROM` 关系？**

- `MotifGroup`：解决**检索聚合**（每组只展示一张，消除 4 倍重复）和**属性继承**
  （地域、技法标在组上，4 个变体自动共享）
- `DERIVED_FROM`：解决**数据溯源**（版权追溯）和**教学深度**（路径查询练习）

**关键设计**：标注属性挂在 `MotifGroup` 而非 `Image` 上。这意味着回填标注时只需标 250 次
而不是 1000 次，且口径调整只改一处——这是"不用重构"能真正成立的原因。

6. **生成结果不自动刷新**（仅 ComfyUI 后端）：需手动点「查询进度」。这是有意的设计——
   ComfyUI 任务是异步的，自动轮询会占用服务器资源。
   云端 API 后端是同步返回的，不需要轮询。

7. **机器参考值仅供参考**：标注表里 `ref_` 前缀的字段是程序统计的，
   实测**图片主色常被黑色边框主导**，已在表头标注「常为背景，勿直接采信」，
   最终以人眼判断为准。详见 `annotation/标注操作指南.md`。

测试过程中发现并修复了 **6 个真实缺陷**，其中两个是**静默失败**（不报错但结果错）：

- **多纹样组合静默丢弃第二张图**：用单图模板做组合会产出"假组合"作品。
  现已加占位符强制校验，缺一个就拒绝提交。
- **标注合并静默失败**：标注表用中文表头、合并程序按英文 key 取值，
  填了数据却显示"更新 0 行"。现已加中英映射与列名警告。

另外还有一个**误导性错误**：ComfyUI 连不上时显示"服务返回状态码 502"，
实际是系统代理拦截了本地请求。现已区分「服务没启动」与「被代理拦截」。
